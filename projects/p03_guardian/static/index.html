What it is doing

Three layers run on every message: the amount parser, the intent and slot parser, and the coercion check. This panel shows what each one made of the last thing you said.

The three rules it will not break

Nothing executes without a reply that is exactly a yes. "hmm", "acha" or a new sentence are not consent, and the question is asked again.
Every amount is read back in words before it moves. pandrah hazaar and dedh hazaar do not sound alike; 15,000 and 1,500 look alike.
When two pressure patterns appear together, there is no confirmation to press. No "proceed anyway" exists, because the user under pressure is the one who would press it.

End-to-end properties

Hash-chained audit trail

Every action and every refusal, each entry carrying the hash of the one before it. Refusals are logged as deliberately as transfers: a log that holds only what happened cannot answer whether the user was warned.

Contacts in the sandbox

Two of these share a name prefix on purpose: "Rashid" is genuinely ambiguous, and the assistant has to say so rather than pick.

Coercion families

The score is the number of distinct families present, not the number of matched phrases. One family warns; two block.

Replies that count as yes and no

Closed sets. Everything outside them is unclear, and unclear is never consent.

Standard library only — no model, no GPU, no API key. Nothing here moves real money.
