Switchboard

ISO 8583 workbench — decode traffic, generate lifecycles, check the invariants

What this measures

A decoder and a rule list both look convincing while they are only ever shown correct traffic. These numbers come from breaking valid traffic on purpose and counting what the project rejects.

Random corruption, rejection rate by group

One character of a valid message replaced at random, 2,000 times. The three groups have three different correct answers, which is why the overall rate is not the headline.

Table view

Fault catalogue

Each fault is modelled on a production defect and labelled with the rule meant to catch it. A fault caught only by a different rule is reported as such, because the rule it was written for is then still unproven.

Where the parser cannot help

Decode a raw message

Paste an ASCII-framed message: 4-character MTI, 16-character hex bitmap, then the data elements.

Generate a transaction lifecycle

Every step is packed and re-parsed before it is shown, so anything the codec would reject never reaches this page.

Check a flow against the invariants

One raw message per line, in the order they crossed the wire. Requests and responses are told apart by their MTI, not by the order you paste them in.

The invariants

Each one is a thing that, when it breaks in production, produces either a cardholder debited for cash they never received or a reconciliation break someone unpicks by hand.

Data element dictionary

The 50 elements a card switch actually populates, with the length discipline the codec enforces.
